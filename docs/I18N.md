# I18N — Desain Fitur Bilingual `/id` (English Default)

> **Status:** ✅ DIEKSEKUSI — berjalan sejak 5 Aug 2026 (`/en` default via redirect dari `/`, `/id`; 20 route SSG; lint & build lolos).
> **Konteks:** Dokumen ini berisi desain & rencana fase bilingual yang sudah diterapkan. Detail arsitektur terkini: `app/[lang]/`, `data/{en,id}/` + `data/ui/{en,id}.ts`, `lib/i18n.ts`.
> **Bahasa dokumen:** Bahasa Indonesia (sesuai keputusan user).

---

## 1. Keputusan & Prinsip

| Aspek | Keputusan |
|---|---|
| URL | `/` = English (default), `/id` = Bahasa Indonesia |
| Pendekatan | **i18n statis kustom per-locale** — BUKAN `next-intl` / library pihak ketiga |
| Alasan | Konten adalah **data terstruktur** (array objek) + markdown, bukan string ICU; UI strings sedikit; site statis tanpa routing dinamis lain |
| Slug | **Tetap sama** di kedua bahasa (ID stabil, netral bahasa) |
| Skope | 5 halaman + 404; artikel blog 2 bahasa (file markdown terpisah) |
| SEO | `hreflang` (`en`/`id`/`x-default`) + sitemap per locale |

**Kenapa bukan `next-intl`:** library tsb mengoptimalkan string ICU + penyimpanan pesan terpusat untuk app dinamis/SSR kompleks. Di sini porsi terbesar adalah **konten array** (proyek, journey, blog) yang lebih natural sebagai modul data terpisah per locale; menambah `next-intl` hanya menambah lapisan tanpa nilai sebanding.

## 2. Arsitektur URL & Routing

```
/                    → app/page.tsx          (English, redirect tidak diperlukan)
/id                  → app/id/page.tsx       (Indonesian) [ALTERNATIF LAYOUT-A]
```

**Pola yang direkomendasikan:** `app/[lang]/` + `generateStaticParams(["en","id"])`.

```
app/
  [lang]/
    layout.tsx               # <html lang> per locale + Header/Footer (lang-aware)
    page.tsx                 # Home
    about/page.tsx
    journey/page.tsx
    projects/page.tsx
    blog/page.tsx
    blog/[slug]/page.tsx     # generateStaticParams gabungan: slug × locale
    not-found.tsx
  page.tsx (opsional)        # redirect("/en") ATAU render ulang Home English
```

Pertimbangan:
- **Root `/`**: pilih satu dari dua opsi — (a) `redirect('/en')` (satu kanonik, lokasi jelas) atau (b) render Home English langsung di `/` tanpa pindah. Rekomendasi: **(a)** agar `hreflang`/sitemap satu-satunya kanonik = `/en`, menghindari konten duplikat.
- **`generateStaticParams`**: `[{lang:"en"},{lang:"id"}]` → semua halaman pre-render statis, tanpa middleware/rewrite.
- **`params`**: `async function Page({ params }: { params: Promise<{ lang: string; slug?: string }> })` lalu `const { lang } = await params;` (Next 15+).
- **Tanpa middleware**: routing statis lebih sederhana & build-friendly.

## 3. Strategi Konten per Locale

### 3a. UI strings → dictionary

`data/locales/<lang>/ui.ts`:

```ts
export const ui = {
  en: {
    navHome: "Home",
    searchPlaceholder: "Search articles…",
    emptyBlog: "No posts found — try a different keyword or tag.",
    themeLight: "Enable light mode",
    // ...
  },
  id: {
    navHome: "Beranda",
    searchPlaceholder: "Cari artikel…",
    emptyBlog: "Tidak ada artikel ditemukan — coba kata kunci atau tag lain.",
    themeLight: "Aktifkan mode terang",
    // ...
  },
} as const;

export type Locale = keyof typeof ui;
```

Komponen menerima `lang` via props (atau `LanguageProvider` kecil berbasis React context, tanpa library).

### 3b. Data konten → modul per locale

```
data/
  en/  site.ts  main.ts  about.ts  techStack.ts  journey.ts  projects.ts  blog.ts
  id/  site.ts  main.ts  about.ts  techStack.ts  journey.ts  projects.ts  blog.ts
content/blog/
  <slug>.en.md
  <slug>.id.md
```

- `data/site.ts` memuat `siteMetadata` + `pageMetadata` per locale (judul/deskripsi meta mengikuti bahasa).
- Struktur tipe (`lib/types.ts`) **sama** di kedua locale — hanya nilai string yang berbeda.
- Proyek/tool/teknologi umumnya sudah English & identik; duplikasi kecil tidak masalah (nilai konsisten), atau ekspor dari satu sumber bila murni identik.

### 3c. Artikel blog

- Baca berdasarkan locale: `content/blog/<slug>.<lang>.md`.
- `getMarkdown(slug, lang)` di `lib/blog.ts` menambah argumen `lang`; fallback: jika `<lang>` belum ada, gunakan `.en.md`.
- `readingTime` tetap dihitung per versi bahasa.

## 4. Komponen yang Harus Lang-Aware

| Komponen | Perubahan |
|---|---|
| `components/Header.tsx` | Link nav diberi prefix `/lang`; tambah **language switcher** (EN/ID toggle di desktop + drawer mobile); `aria-label` dari dictionary |
| `components/Footer.tsx` | Link & teks dari dictionary |
| Semua halaman | Baca `lang` dari params → teruskan ke komponen |
| `app/blog/[slug]/page.tsx` | Path artikel per locale; canonical `hrefLang` |
| `app/not-found.tsx` | Teks dari dictionary (butuh konteks lang) |
| `app/sitemap.ts` | Generate entry untuk tiap locale + `alternates.languages` |

## 5. SEO

- **`<html lang>`** diset per locale di `app/[lang]/layout.tsx`.
- **Hreflang** di `generateMetadata` setiap halaman:
  ```ts
  alternates: {
    languages: {
      "en": "/en/...",
      "id": "/id/...",
      "x-default": "/en/...",
    },
  }
  ```
- **Sitemap** (`app/sitemap.ts`): satu entry per halaman per locale dengan `alternates.languages`.
- **Kanonik** hanya di `/en` & `/id` (bukan `/` bila root redirect).
- `metadataBase` di root layout.

## 6. Daftar Fase Implementasi (saat dieksekusi)

1. Buat `data/locales/<lang>/ui.ts` (inventaris string: Header, Footer, form, empty states, toast, aria-label — ambil dari checklist `docs/ENGLISH.md` §2c).
2. Buat `data/en/` (pindahkan & tentukan sumber konten English saat ini) + `data/id/` (tulis ulang konten Bahasa Indonesia).
3. Pindah `content/blog/*.md` → `<slug>.en.md` + tulis `<slug>.id.md`.
4. Ubah struktur folder ke `app/[lang]/` (pindahkan halaman yang ada), tambah `generateStaticParams`, update `lib/blog.ts` & `lib/utils.ts` (`formatDate` per locale).
5. Tambah language switcher di Header/Footer + `LanguageProvider` (context kecil).
6. Update SEO: sitemap + hreflang + `<html lang>`.
7. Keputusan root: redirect `/` → `/en`.
8. Verifikasi: `npm run lint` + `npm run build` (harus tetap statis, tanpa middleware) + manual test kedua bahasa.

## 7. Non-Goals i18n

- ❌ Tidak memakai `next-intl` / library i18n lain.
- ❌ Tidak menambah middleware/rewrite dinamis.
- ❌ Tidak menerjemahkan slug, nama properti, nama tool, atau credential ID.
- ❌ Tidak membuat fitur dinamis baru (dictionary tetap statis).
